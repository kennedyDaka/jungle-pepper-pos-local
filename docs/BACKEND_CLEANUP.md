# Backend Cleanup Record

## Current Backend State

The project was originally made local-only, then later connected to Supabase incrementally. Runtime data now comes from Supabase service queries, not browser-local seeded data.

No GitHub, Lovable Cloud, Cloudflare, old backend URL, old auth provider, or old storage provider is configured. Supabase is now the only runtime backend target.

## Removed Dependencies And Configuration

- `@lovable.dev/vite-tanstack-config`: removed because it bundled Lovable-specific Vite behavior, environment injection, Cloudflare build assumptions, and Lovable project conventions.
- `@cloudflare/vite-plugin`: removed because this project is not being deployed to Cloudflare Workers during local-only development.
- `@supabase/supabase-js`: re-added during the live Supabase connection phase as the only backend client.
- `bcryptjs` and `@types/bcryptjs`: removed because local mock auth does not hash passwords and no backend password verification runs in this app.
- `.env`: removed because it contained live Supabase project URL, project ID, and publishable key values.
- `.lovable/`: removed because it contained Lovable project metadata and a Lovable-generated implementation plan.
- `wrangler.jsonc`: removed because Cloudflare deployment is out of scope for the local-only app.
- `bun.lock`: removed because the requested workflow is `npm install` and `npm run dev`; `package-lock.json` is now the npm lockfile.
- `supabase/config.toml`: removed because it contained the old Supabase project ref.
- old `supabase/migrations/*.sql`: removed because they were tied to the previous backend state and auth/RLS assumptions.
- `src/integrations/supabase/*`: removed because those generated clients required Supabase environment variables and threw Lovable Cloud connection errors.

## Environment Variables

Supabase runtime values live in:

- `.env.local`
- `.env.l`

Current values:

```env
VITE_BACKEND_MODE=supabase
VITE_ENABLE_SUPABASE=true
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
```

The Vite app reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Do not use `NEXT_PUBLIC_*` keys in this TanStack/Vite frontend.

## Supabase Connection Point

Supabase is introduced behind the repository/service boundary:

- `src/services/repositories/supabaseClient.ts` owns the typed Supabase browser client.
- `src/services/repositories/supabaseRepository.ts` exposes current repository status.
- `src/types/database.ts` should be replaced with generated Supabase database types after the live schema is applied.
- service files in `src/services/*.ts` should keep their public method names so UI routes do not need another rewrite.
- environment reads should remain centralized in `src/lib/env.ts`.
